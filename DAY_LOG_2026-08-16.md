### 6.1 `BUSINESS_PLAN.pdf` still shows a fake contact address
Its footer reads `hello@chalkline.example`. `TAKEOFF_sample.pdf` reads `<EMAIL> · <MOBILE>`. **Two documents in the same repo, same brand, different contact conventions.** The PDF was simply not re-rendered after the placeholder change. One command fixes it.

### 6.2 The floors-only count is wrong in two files, and one of them is the business plan
`STRESS_REPORT.md:393` and `BUSINESS_PLAN.md:291` both say **"one was genuinely unreadable and six could be measured for floors but not walls."**
The round-2 scoreboard in the same report says **2 unreadable** (`ncc`, `phone-scan`) and **5 floors-only**. The 1/6 split is the round-1 framing, written before the gate fix moved `ncc` from pass to fail, and never updated. **A risk assessment in the business plan is quoting a superseded number from a report that contradicts it three sections earlier.**

### 6.3 The stress report opens with a headline it later reverses
`STRESS_REPORT.md` line 14 states **"5 passed, 4 rejected"** with no marker that this is round 1. Round 2's **"2 passed, 7 rejected"** is 380 lines further down. A new owner reads the top and takes away the wrong number. The document needs a status line at the top saying which round is current.

### 6.4 The ANSWER PACK is four pages; two documents say three
`BRAND.md:169` and `TAKEOFF_METHOD.md:432` both say **"ANSWER PACK — pages 1–3"**, and `TAKEOFF_METHOD.md:499` heads a section **"Page 3 — the answer form."** After the final QC added the FLAGGED FOR YOU box, the actual layout is p1 answer, p2 rooms + site notes, **p3 flagged**, **p4 answer form**. The spec and the artefact disagree. Flagged in the QC commit message but not fixed in the docs.

### 6.5 `SPEC.md` §3 describes a five-section document that no longer exists
It lists ORDER THIS / CHECK THESE / ROOM BY ROOM / *other trades* / HOW WE GOT THESE NUMBERS. The real document has SITE NOTES, FLAGGED FOR YOU, an assumptions answer form, and an account form — none of which appear. `SPEC.md` is the output contract and it is stale.

### 6.6 `SPEC.md` and `TAKEOFF_METHOD.md` still call the product "TAKEOFF"
Everything else moved to `CHALKLINE`. These two didn't. A reader can't tell whether TAKEOFF is the company, the product, the module, or an old name.

### 6.7 The brand is sourced from `BRAND.md` only in the *chrome*, not the *content*
`render_pdf.py` reads name and tagline from `BRAND.md` — good. But `BUSINESS_PLAN.md`, `README.md` and `TAKEOFF_sample.md` contain the literal string `CHALKLINE` in body text, baked in at generation time. **A rename in `BRAND.md` updates the page headers and silently leaves the body copy wrong.** The guarantee is half-true and reads as fully true.

### 6.8 `INTAKE.md` documents 10 gate checks; the code has 12
`INTAKE.md` §C's table was written for the original gate. Job 1 added `text_quality` and `wet_area_elevations`. The published intake contract no longer matches what the gate actually enforces — and this is the document a customer would be sent to explain a rejection.

### 6.9 `backtest/RESULTS.md` is committed but is a moving target
It is regenerated by every harness run and **overwritten with a single-row scoreboard whenever `--only` is used.** It currently holds the 9-set round-2 run, but the Job 2 runs in flight will overwrite it with a 1-set table. A committed file that a background process is rewriting is a merge accident waiting to happen. Either stop committing it, or write per-run files.

### 6.10 The test corpus is not reproducible from the repo
`backtest/inbox/` is correctly gitignored (third-party copyright), but there is **no script to re-fetch the 9 sets from `SOURCES.md`**, and three of the source hosts already returned `403` during collection. A new owner cloning this repo cannot re-run the stress test at all. `SOURCES.md` also documents that `phone-scan-of-da-plans.pdf` is **derived**, not found — honest, but it means one of nine cases only exists on this machine.

### 6.11 Thresholds are tuned on nine sets and are stated as if settled
`MIN_CHAINS_PER_PAGE = 0.4`, `MIN_WET_KEYWORDS = 4`, `TITLE_CONF = 0.30`. Every one was fitted to the same nine files it is evaluated on. The separation is genuinely wide (0.12 vs 1.6 chains/page), but **there is no held-out set.** Presenting a fit as a validation is the exact error the accuracy doctrine exists to prevent, and the report does not say this plainly enough.

### 6.12 The word-hit quality score is dead weight
Job 1 added it and it demonstrably does not separate — OCR set 0.315, good set 0.307. `STRESS_REPORT.md` says so honestly, but the check is still wired as a **hard** gate at 0.15. It currently blocks nothing and could one day block something legitimate. Either give it a job or take it out.

It still describes the original 6-step build including "expected ballpark ~7.1 m² and ~19.9 m²" — figures the repo has since demonstrated to be naive rectangle products. Nothing marks it as historical.
